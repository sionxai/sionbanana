## 1. 미션

1인 콘텐츠 제작자가 캐릭터·장소·오브젝트의 일관성을 유지한 다중 컷 시각 콘텐츠를
더 빠르고 안전하게 완성하도록 돕는다.

Sion Banana는 단일 이미지를 많이 만드는 도구가 아니다. 시나리오에서 레퍼런스,
스토리보드, 검수, 정리, 내보내기까지 이어지는 **로컬 우선 제작 워크플로우**다.

## 2. 사업 모델

### 2.1 고객과 해결할 일

- 핵심 고객: 영상·숏폼 1인 제작자, AI 영상 강사, 스토리보드·콘티 작가
- 핵심 과업: 여러 컷에서 인물·공간·소품의 일관성을 유지한 제작용 산출물 완성
- 핵심 문제: 컷별 외형 불일치, 반복 생성, 결과 정리와 검수에 드는 수작업
- 핵심 가치: 레퍼런스 고정, 병렬 생성, 씬별 검수·정리·내보내기를 하나의 흐름으로 연결

### 2.2 현재 단계

- 현재는 **소유자 운영형 로컬 생산성 제품**이며, 수익화 이전의 제품 검증 단계다.
- 사용자의 PC와 ChatGPT 구독 자격을 활용하고 별도 멀티테넌트 백엔드나 자체 과금
  시스템을 운영하지 않는다.
- 현재 구현은 생성 이미지·영상과 메타데이터를 로컬 파일시스템에, 일부 브라우저 편집
  상태를 `localStorage`에 저장하는 혼합 단계다. SQLite 메타데이터 통합은 결정됐지만
  아직 구현 완료되지 않았다.
- 경제적 가치는 기능 수가 아니라 제작 시간 절감, 재생성 감소, 납품 가능한 산출물
  증가로 측정한다.
- 구독료, 라이선스, 유료 배포 방식은 아직 결정하지 않았다.

### 2.3 수익화 전환 조건

다음 조건을 모두 충족하기 전에는 과금 기능을 만들지 않는다.

1. 핵심 KPI를 실제 제작 20회 이상에서 측정한다.
2. 핵심 워크플로우 완료율과 데이터 보존 기준을 충족한다.
3. 인증·모델 호출 방식의 배포 및 상업적 이용 조건을 확인한다.
4. 핵심 고객이 반복 사용하고 비용 지불 의사를 보인다는 증거를 확보한다.

## 3. 포지셔닝

**Sion Banana는 일관된 다중 컷 콘텐츠를 만드는 1인 제작자를 위한 로컬 AI
프리프로덕션 스튜디오다.**

- 일반 이미지 생성기와 달리 레퍼런스 일관성과 시나리오 단위 완성을 최적화한다.
- 범용 디자인 편집기와 달리 생성, 검수, 정리, 내보내기에 집중한다.
- SaaS 협업 도구와 달리 로컬 단일 사용자의 데이터 통제와 빠른 개인 워크플로우를
  우선한다.
- 웹툰과 모션은 별도 제품이 아니라 동일한 레퍼런스·스토리보드 자산을 재사용하는
  후속 출력 형식이다.

## 5. KPI

### 5.1 측정 원칙

- KPI는 기능 출시가 아니라 실제 제작 결과를 측정한다.
- 최초 기준선 기간은 **2026-08-04~2026-08-18**이며, 실제 제작 20회가 부족하면
  기간보다 표본 수를 우선한다.
- 생성 1회가 아니라 사용자가 검수·저장·내보내기까지 마친 묶음을 `제작 1회`로 센다.
- 초기 목표는 기준선 수집 후 버전 로그와 결정 로그를 통해 조정한다.

### 5.2 우선순위 KPI

| 순위 | KPI | 정의 | 초기 목표 |
|---:|---|---|---:|
| 1 | 납품 가능 워크플로우 완료율 | 시작한 제작 중 저장·검수·내보내기까지 완료된 비율 | 90% 이상 |
| 2 | 레퍼런스 일관성 통과율 | 12컷 이상 묶음에서 인물·공간·소품이 재생성 없이 검수를 통과한 컷 비율 | 80% 이상 |
| 3 | 제작 시간 절감률 | 동일 종류 산출물의 기존 수작업 대비 완료 시간 감소율 | 50% 이상 |
| 4 | 재작업률 | 납품 전 재생성 또는 수동 교체가 필요했던 컷 비율 | 25% 이하 |
| 5 | 데이터 보존 신뢰도 | 완료 산출물의 유실·메타데이터 불일치·복구 불가 건수 | 0건 |

보안 사고, 인증정보 노출, 사용자 파일 손실은 최적화 대상 KPI가 아니라 **0건을
유지해야 하는 출시 차단 기준**이다.

### 5.3 KPI가 아닌 것

- 커밋 수, 코드 줄 수, 페이지·API·기능 수
- 생성한 이미지의 총개수와 모델 호출량
- 테스트를 실제로 실행하지 않은 상태의 체크리스트 완료 수
- 핵심 제작 흐름과 무관한 시각적 화려함
- 공개 배포가 승인되지 않은 단계의 가입자·트래픽 수

## 7. 운영 원칙

1. **핵심 흐름 우선:** 스토리보드 중심 제작 흐름의 KPI가 확장 기능보다 우선한다.
2. **로컬 우선:** 생성물과 메타데이터는 사용자가 통제하는 로컬 저장소에 보존한다.
3. **사람 검수:** 자동화는 초안을 만들고 비용을 줄이지만 최종 품질 판정은 사용자가 한다.
4. **증거 기반 완료:** 테스트 실행 결과나 실물 확인 없이 완료로 판정하지 않는다.
5. **작업지시 연결:** 코드 변경은 COMPANY 조항과 연결된 작업지시 ID, 완료 기준,
   검수 결과를 가져야 한다.
6. **작은 범위:** 공통 기반을 안정화하기 전 기능 범위를 동시에 넓히지 않는다.
7. **보안 우선:** 토큰과 비밀값은 서버 경계 밖으로 노출하지 않으며 로그에 남기지 않는다.
8. **외부 의존성 현실화:** 모델명, 응답 형식, 약관이 바뀔 수 있음을 제품 리스크로 관리한다.
9. **현황판 보고:** CEO는 주요 작업 마무리(검수·병합·주요 결정 기록)마다 `docs/dashboard.html`
   현황판을 갱신해 대표자에게 보고하며, 갱신 즉시 크롬 브라우저로 띄워 표시한다.
   현황판은 뷰어 전용이며 진실의 원본은 항상 정본 문서다.

## 9. 확인된 불일치와 미결정

### 해결 방향이 정해진 불일치

- 저장 방식: PRD의 파일시스템+JSON 임시 가정보다 `DEC-002`의 SQLite 메타데이터+
  파일시스템 이미지 결정을 우선한다.
- 제품 범위: 최근 모션·웹툰 개발은 허용하되 핵심 KPI 검증을 통과해야 확장 완료로
  판정한다.

### 2026-08-16 구현 기준 사실

- 인증은 로컬 웹 장치 로그인 결과(`data/codex-auth.json`)를 우선하고 Codex CLI 인증
  파일을 폴백으로 읽는다. 공개 서비스용 인증 계약은 아니다.
- 텍스트·이미지 요청의 코드 기본 모델은 모두 `gpt-5.5`이고, 이미지 모드는 Responses
  요청에 `image_generation` 도구를 붙인다. 환경변수로 모델을 재정의할 수 있다.
- 생성 이미지·영상 및 메타데이터는 `data/images`, `data/videos` 파일시스템에 저장한다.
  캐릭터·스토리 프로젝트 등 일부 클라이언트 상태는 아직 `localStorage`다.
- Webtoon Studio 라우트·컴포넌트·저장 모듈·테스트는 로컬 untracked WIP이며 이 후보의
  clean checkout 구현이나 완료 기능으로 간주하지 않는다.

### 아직 결정하지 않은 것

- 최종 수익모델과 가격
- 공식 배포 채널과 지원 범위
- 영상 생성 공급자 및 활성화 시점
- 소프트 삭제·휴지통의 전체 제품 공통 정책

미결정 항목은 작업 세부값으로 임의 확정하지 않는다. 구현을 차단하면 CEO 안건으로
올리고, 결정 즉시 이 문서의 결정 로그와 버전 로그를 함께 갱신한다.
