# Sion Banana Webtoon

세로 웹툰(만화)을 시나리오 한 편에서 완성형으로 뽑는다. `sionbanana-image-gen`이 가로 키프레임/스토리보드 중심이라면, 이 스킬은 **세로 9:16 + 그림 안에 통합된 한글 말풍선 + 세로 이어붙이기**를 더한 웹툰 전용 워크플로우다.

> ★ **말풍선 방식 = 그림 안에 통합 생성(A안)**: 말풍선과 한글 대사를 **프롬프트에 넣어 이미지 생성 단계에서 그림과 함께 그린다.** 사후에 PIL로 얹지 않는다(그렇게 하면 스티커처럼 떠 보이고 꼬리가 화자를 안 가리킴 — 실측 확인). 시온바나나는 한글 렌더링이 정확해서, 짧은 대사는 말풍선 안에 오타 없이 그려진다(실측: "달님... 나도 한 번 가보고 싶어" 정확 렌더링). 사후 PIL 합성(`webtoon-balloons.py`)은 **세로 이어붙이기 전용**으로만 쓴다(`--no-balloon`).
> 관계: 시온바나나 앱의 "웹툰 생성" 에디터(말풍선 드래그·4종 모양·export)가 완성되면, 텍스트 수정이 쉬운 별도 레이어 방식으로 보강된다. 그 전까지 이 통합 생성 방식이 가장 자연스럽다.

## Prerequisites

- 시온바나나 프로젝트 디렉토리에서 실행, 서버 포트 `3002` (launchd 상주 `com.sionbanana.server` — kill해도 자동 재기동. 재빌드 반영: `npm run build && launchctl kickstart -k gui/501/com.sionbanana.server`).
- `curl -s http://localhost:3002/api/health` 로 `"authenticated": true` 확인.
- 한글 폰트: macOS `AppleSDGothicNeo`(스크립트가 자동 탐색). Pillow 설치 필요.

## Workflow

### Step 0: 시나리오 → 세로 웹툰 컷 분할
시나리오를 세로 웹툰 흐름으로 나눈다. 각 컷은 **장면 + 식자 요소(대사·효과음 등)**를 갖는다.
- 컷 수: 짧은 에피소드 8~12컷. 시작(상황)→전개→절정→여운 흐름.
- 텍스트는 **짧게**(말풍선당 1~2줄). 긴 문장·여러 말풍선은 한글이 깨질 위험.
- 컷마다 등장 캐릭터(레퍼런스 연결)를 정하고, **각 텍스트를 식자 type으로 태깅한다(아래 "식자 체계" 참조)** — 같은 대사라도 일반 대사인지 외침인지 효과음인지에 따라 표현이 달라진다.
- 각 컷의 식자는 `lettering` 목록으로 적는다: `[{ "type": "...", "text": "...", "speaker": "...", "placement": "...", "tailTo": "..." }]`. 단순 대사 한 줄이면 `dialogue: "화자: 대사"`만 써도 된다(= type speech로 간주).

### Step 1: 캐릭터 시트 생성/확인
사용자가 시트를 첨부했으면 업로드해 쓰고(`/api/story-references`), 없으면 **웹툰 일러스트 스타일로 생성**한다(주연·주요 조연 각 1장).

```
Character reference sheet for {인물}, Korean webtoon illustration style with soft cel shading and clean lineart.
Left half: full-body front view and back view on a neutral light background.
Right half: 4-panel face grid (front, 3/4 left, 3/4 right, profile).
{종/나이/체형}, {헤어}, {의상·소품}, {표정·분위기}. Consistent character identity across all views.
```
- `--category "{project}" --slug "ref-char-{인물}" --quality high --aspect "16:9"`
- 생성물은 즉시 `/api/images/<id>`로 접근 가능(별도 업로드 불필요). 이 id를 컷 `referenceGallery`에 건다.

### Step 2: 세로 컷 일괄 생성 (말풍선을 프롬프트에 통합)
`sionbanana-image-gen`의 storyboard spec→run→organize를 **세로 + 말풍선 통합** 설정으로 쓴다.

- `defaults.size` = **`"2k-9:16"`** (= 1152×2048, 세로 웹툰).
- 각 컷 `referenceGallery`에 등장 캐릭터 시트 id(캐릭터 일관성 = 앵커링).
- 컷 프롬프트는 **장면 + 캐릭터 유지 + 식자(타입별)**를 한 번에 적는다:
  - "한국 웹툰 일러스트 스타일, soft cel shading, clean lineart"
  - "첨부된 캐릭터 외형을 그대로 유지하라"
  - **식자 문장(아래 "식자 체계"의 타입별 템플릿)**
- 식자 텍스트는 «» 로 감싸 명확히 구분, 인물 얼굴을 안 가리는 여백에. 한 컷에 말풍선은 1개가 가장 안정적(효과음 sfx는 추가 가능).

> ★ **배경 텍스트 고정**: 말풍선 밖에도 글자가 들어갈 표면(칠판·간판·현판·게시물·배너)이 컷에 보이면 **정확한 문구를 프롬프트에 명시**하거나 "빈 칠판"처럼 비어 있음을 명시한다 — 지정하지 않으면 모델이 그럴듯한 가짜 한글을 지어내 채운다 (실측: 교실 칠판에 지시 없던 가짜 판서, 국가명 액자가 엉뚱한 학교명으로 둔갑). 상세 규칙·금지 문구 패턴은 `sionbanana-image-gen`의 "배경 텍스트 고정" 섹션.
> ★ **장소·공간 일관성**: 같은 배경이 여러 컷 반복되면 `sionbanana-image-gen`의 Phase 1d(장소·오브젝트 시트)와 Phase 1e(마스터샷 앵커링·좌우 축선 규약)를 웹툰 컷에도 그대로 적용한다 — 캐릭터 시트만 걸면 배경이 컷마다 새로 그려진다.

## 식자 체계 (Lettering) ★핵심
같은 대사라도 **감정·상황에 따라 말풍선 모양·글씨·배치가 달라지고, 효과음·의태어는 말풍선 없이** 그림에 직접 그린다. 각 텍스트를 아래 `type`으로 태깅하고, 타입별 프롬프트 문장을 쓴다. (특정 폰트 직접 지정은 AI 생성이라 불가 → **글씨 느낌을 묘사**로 근사.)

| type | 쓰임 | 프롬프트 문장 패턴 |
|---|---|---|
| `speech` | 일반 대사 | "깔끔한 흰색 **둥근** 말풍선 안에 한글로 «{대사}», 또렷한 손글씨체. 뾰족한 꼬리는 {화자} 쪽." |
| `shout` | 외침·강조 | "**끝이 뾰족한 폭발형(가시 모양)** 말풍선 안에 한글로 «{대사}!», **굵고 큰 거친 손글씨**. 꼬리는 {화자} 쪽." |
| `thought` | 속마음·독백 | "**몽글몽글 구름 모양** 생각 풍선 안에 한글로 «{대사}», 부드러운 손글씨. 꼬리는 작은 동그라미 방울들로 {화자} 쪽." |
| `whisper` | 속삭임 | "**작고 옅은 점선 테두리** 말풍선 안에 한글로 «{대사}», 가늘고 작은 글씨." |
| `narration` | 나레이션·해설 | "화면 {상단/하단} 모서리에 **흰색 불투명 직사각 박스 + 가는 검은 테두리**, 그 안에 한글로 «{문구}», 정갈한 고딕 느낌. (말풍선 꼬리 없음)" |
| `sfx` | 효과음·의태어 (둥실둥실·허겁지겁·쿵·두근두근) | **"말풍선 없이"** 그림 위 동작 주변에 한글로 «{의성어/의태어}»를 **역동적이고 반투명한 큰 손글씨 그래픽**으로 흩뿌리듯 배치, 움직임 방향을 따라 기울어지게. |

규칙:
- **sfx는 절대 말풍선을 그리지 않는다.** "말풍선 없이 그림 위 그래픽 손글씨"를 명시. (예: 떠오르는 컷 → «둥실둥실», 달려가는 컷 → «허겁지겁»)
- 한 컷에 speech/shout 등 말풍선은 1개 권장, 거기에 sfx 1개를 더할 수 있다(말풍선+효과음 공존 OK).
- shout는 굵고 크게, whisper는 작고 옅게 — **글씨 크기·굵기 대비**로 감정을 준다.
- 위치는 인물 얼굴·핵심을 안 가리는 여백으로 프롬프트에 지정. 한글은 "오타 없이 정확하게 렌더링" 항상 명시.

### 식자 자동 설계 (시나리오 → 식자 판단)
시나리오를 받으면 **각 컷의 대사·상황을 아래 규칙으로 자동 분류**해 type을 정한다(즉흥 판단 금지, 규칙 적용).

**대사 → type 판단 규칙:**
| 신호 | type |
|---|---|
| 느낌표·외침·놀람·고함 (예: "안 돼!", "우아—!") | `shout` |
| 속마음·혼잣말·독백 (따옴표 없는 생각, "…일까?") | `thought` |
| 작게·은밀·소곤 (지문에 "속삭이며") | `whisper` |
| 해설·시간 경과·심리 서술 (화자 없는 서술문) | `narration` |
| 그 외 일반 대화 | `speech` |

**상황 → 효과음(sfx) 라이브러리** (해당 동작이 있으면 sfx를 추가, 없으면 안 넣음 — 남발 금지):
| 동작/상황 | sfx 예시 |
|---|---|
| 떠오름·부유 | 둥실둥실, 두둥실 |
| 빠른 이동·달림 | 다다닥, 휙, 슈웅 |
| 허둥지둥·당황 | 허겁지겁, 화들짝 |
| 먹기 | 오물오물, 냠냠 |
| 빛남·반짝임 | 반짝반짝, 반짝 |
| 충격·부딪힘 | 쿵, 쾅, 퍽 |
| 긴장·두근거림 | 두근두근, 콩닥콩닥 |
| 정적·고요 | (효과음 없음 — 여백으로) |
| 웃음·울음 | 까르르, 훌쩍 |

**VFX 연출(P2, 가능하면):** 놀람·강조 컷엔 "집중선(放射 모양 배경선)", 빠른 동작엔 "속도선", 분노엔 "불꽃·핏대", 당황엔 "식은땀·세로줄 그림자" 같은 만화적 효과를 프롬프트에 한 줄 더한다. (모양 일관성은 보장 안 됨.)

원칙: **한 컷에 말풍선 1개 + (필요시) sfx 1개**. 효과음은 동작이 있을 때만, 작품 톤에 맞는 의태어로. 조용한·서정적 컷은 sfx 없이 비운다.

### 칸 레이아웃 (한 이미지 안의 프레임 구성) ★자동 설계

> ★★ **칸을 나누는 "이유"가 먼저다 (가장 중요)**: 칸 분할은 *레이아웃을 적용*하는 게 아니라 **"한 칸으로는 표현이 안 되는 연출 이유"가 있을 때만** 한다. 그냥 두 인물을 좌/우(또는 상/하)에 욱여넣으려고 **화면을 기계적으로 반 자르면 의미가 없다 — 그건 투샷 한 칸(single)이 더 자연스럽다.** (실측 실패: "두 인물 대비"라며 세로로 반 자른 컷은 그냥 한 그림을 선으로 가른 느낌이었다.)
>
> **나누는 진짜 이유 → 그때 쓰는 layout:**
> - **시간 분해**(한 동작·감정이 순간들로 이어짐: 떠오름→더 높이, 놀람→깨달음) → `split-h`(위→아래 시간 흐름)
> - **강조·충격**(큰 사건 + 그에 대한 반응·디테일) → `asymmetric`(큰 칸+작은 칸) 또는 `inset`(와이드+모서리 클로즈업)
> - **동시성**(같은 순간 다른 장소/시점) → `split-h`/`split-v`
> - **심리적 거리·단절**(두 인물의 마음이 갈림, 대치) → `split-v` (이때 *비로소* 좌우 분할이 의미를 가짐)
> - **충격·역동·속도** → `diagonal`
>
> 순서: ① 이 장면을 **왜** 나누는가(연출 의도)를 먼저 정한다 → ② 의도에 맞는 layout 선택 → ③ 의도가 없으면 `single`. **"칸이 다양해 보이게"가 목적이 되면 안 된다.**

컷에 `layout`을 지정한다(종류는 아래). 핵심은 위의 "왜 나누는가"이고, 종류는 그 도구다.

**상황 → layout 판단 규칙:**
| 상황 | layout | 설명 |
|---|---|---|
| 단일 순간·풍경·여운 | `single` | 한 화면 통짜(기본) |
| 시간 순서 진행(그리고→그다음) | `split-h` | 가로 분할(위→아래로 읽힘) |
| 두 인물 대비·마주봄·대화 | `split-v` | 세로 분할(좌/우) |
| 한 장면 + 표정/디테일 강조 | `inset` | 큰 칸 + 모서리에 작은 클로즈업 칸(프레임 속 프레임) |
| 충격·역동·긴장·속도 | `diagonal` | 대각선으로 기울어진 칸 |
| 큰 사건 강조 | `asymmetric` | 큰 칸(강조) + 작은 칸 |

각 layout 프롬프트 패턴 — 공통: "칸 사이·가장자리는 {거터색} 여백 + 가는 검은 테두리, 첨부 캐릭터는 모든 칸 동일 외형, 한글 정확 렌더링":
- `split-h`: "위·아래 2칸. [위 칸] {장면A}+«대사A». [아래 칸] {장면B}+«대사B»."
- `split-v`: "좌·우 2칸. [왼 칸] {인물A 장면}+«대사A». [오른 칸] {인물B 장면}+«대사B»."
- `inset`: "전체를 채우는 큰 칸에 {와이드 장면}, 그 **오른쪽 위 모서리에 작은 직사각 칸(인셋)**을 겹쳐 {클로즈업/표정}. 인셋엔 «{짧은 대사}»."
- `diagonal`: "화면을 대각선으로 가른 2칸, 칸이 비스듬히 기울어 역동적. [위] {장면A}. [아래] {장면B}. 속도선·집중선으로 긴장 강조."
- `asymmetric`: "위쪽에 화면 2/3를 차지하는 큰 칸 {강조 장면}, 아래에 작은 가로 칸 {반응/디테일}."

- 칸마다 `[…]`로 **명시 구분**하고 장면+식자를 따로 적는다. 거터 색은 작품 톤(밝음=흰, 어두움=검정).
- ⚠️ **검증 상태(실측)**:
  - ✅ `split-h`(가로 2칸)·`inset`(프레임 속 프레임)·`diagonal`(대각선): 의도대로 그려짐(칸 구분·캐릭터·식자 정확).
  - ❌ `split-v`(세로 2칸): **불안정** — "좌우 2칸"이라고만 하면 **한쪽만 액자로 그리고 다른 쪽은 테두리 없는 배경**으로 나오기 쉽다(실측 실패). 쓰려면 **"화면을 정확히 좌우 절반으로, 양쪽 칸 모두 똑같은 검은 테두리 액자로 둘러싸 동일 크기로"**를 강하게 명시하고, 그래도 한쪽만 칸이면 split-h로 대체하거나 두 인물을 한 칸에 배치한다.
  - `asymmetric`: 미검증.
- 칸 분할은 gpt-image가 **가로(상하)는 안정적, 세로(좌우)는 불안정**하다는 경향이 있다. 세로 대비가 필요하면 split-h(위 인물A/아래 인물B)로 푸는 것도 방법.
- 칸이 많거나(3칸+) 텍스트가 길면 식자·정렬이 흐트러질 수 있다 → 텍스트는 짧게, 검수에서 칸 분할·칸별 텍스트 위치 확인.

```bash
node scripts/storyboard.mjs run data/storyboard/<project>.spec.json --port 3002 --concurrency 2 > data/storyboard/<project>.summary.json
node scripts/storyboard.mjs organize data/storyboard/<project>.spec.json data/storyboard/<project>.summary.json
```

> ⚠️ **rate limit 주의 (실측, 중요)**: 레퍼런스를 연결한 컷을 동시성 4로 돌리면 `input-images per min` 한도(4000)를 쳐서 다수 컷이 502로 실패한다. **`--concurrency`는 2 이하**, 실패분은 `--retry`·긴 `--retry-base-delay`로 부분 재생성. 한 세션에서 이미지를 많이 생성하면 **조직 분당 한도가 누적 포화**되어 짧은 재시도로는 안 풀린다 → **이미지 생성을 수 분간 완전히 멈춰 window를 비운 뒤** 재시도한다. (안전필터 502와 구분: rate limit reason에 "Rate limit reached" 명시.)

### Step 3: 세로 이어붙이기 (+ 컷 사이 거터)
말풍선은 이미 그림에 포함됐으므로 **사후 합성 없이 세로로 잇기만** 한다. 단 **컷을 딱 붙이면 경계가 "잘린 듯" 어색**하므로, 컷 사이에 **거터(여백)**를 넣어 연결성·호흡을 준다(실측: 거터 없으면 잘린 느낌, 있으면 자연스러움).

```bash
python3 scripts/webtoon-balloons.py data/storyboard/<project>.spec.json --no-balloon --gutter 80 --gutter-color black
```
- `--gutter N` : 컷 사이 여백 px(기본 48, 끝단엔 안 넣음). 0이면 딱 붙임.
- `--gutter-color white|black` : **거터 색은 스토리/톤에 맞춘다**.
  - **흰 거터** = 밝은·일상·따뜻한 톤(웹툰 표준).
  - **검은 거터** = 밤·우주·긴장·시네마틱 톤(어두운 작품).
  - 작품 안에서 톤이 크게 갈리면(낮↔밤) 구간별로 다르게 두 번 뽑아 합치는 것도 가능(고급).

산출:
- `data/storyboard/<project>/webtoon-full.png` — **세로 웹툰 완성본**
- `webtoon-preview.png` — 미리보기

> `--no-balloon` 없이 실행하면 PIL로 말풍선을 덧그린다 — A안에서는 **그림에 이미 말풍선이 있으므로 쓰지 않는다**(이중으로 얹힘). legacy fallback일 뿐, 평소 쓰지 않는다.

### Step 4: 전수 검수 (표본 금지)
**모든 컷을 Read로 직접 본다.** 확인 항목:
- **한글 오타** — 모든 식자 텍스트가 정확히 렌더링됐는지(깨진/틀린 글자 없는지). 깨졌으면 짧게 줄여 그 컷만 재생성.
- **배경 텍스트** — 배경에 작게 들어간 간판·액자·판서는 **해당 영역을 크롭 확대해서 직접 읽는다**(썸네일 검수로는 안 읽힘). 확대해 읽지 않았으면 "문제 없음"으로 보고하지 않는다 (실측 실패: 확대 안 하고 통과 보고 → 사용자가 배경 오기를 발견).
- **식자 타입 일치** — speech/shout/thought/whisper/narration이 의도한 모양으로 나왔는지. **`sfx`가 말풍선 안에 갇히지 않고** 그림 위 그래픽으로 나왔는지(갇혔으면 "말풍선 없이" 강조해 재생성).
- **꼬리 대상·가림** — 말풍선 꼬리가 화자를 향하는지, 인물 얼굴/핵심을 가리지 않는지.
- 캐릭터 일관성(컷마다 같은 인물/의상), 다인물 컷의 위치·화자 매핑, 소품 연속성.
- 세로 흐름·읽는 순서가 자연스러운지.
- **누락 컷 0개 확인** — 실패 컷이 남아 있으면 완성본을 만들지 않는다(먼저 채운다).

## 다인물 컷 규칙 (P1)
2명 이상 등장 시 프롬프트에 **인물별 위치·의상·시선·말풍선 꼬리 대상**을 고정한다(안 그러면 외형·화자가 흐려짐):
- "왼쪽에 {A}(의상), 오른쪽에 {B}(의상). {대사}의 말풍선 꼬리는 {화자} 쪽." 
- 각 인물 시트를 `referenceGallery`에 모두 연결.

## 세로 스크롤 연출 (P1, 점진 도입)
웹툰은 컷 길이·여백으로 호흡을 준다. 현재는 9:16 고정이지만, 다음을 점진 적용:
- 리액션/짧은 컷은 위아래를 크롭해 짧게, 감정·배경 컷은 길게(세로 이어붙이기 전 크롭).
- 컷 사이 **흰/검은 여백**으로 호흡(장면 전환·정적). `webtoon-balloons.py`에 gap 옵션 도입 검토.

## Limits & 한계
- **말풍선이 그림에 통합 생성(A안)되므로 텍스트 수정 = 재생성**이다(쉬운 편집은 앱 웹툰 기능 완성 후 별도 레이어로).
- **한글 정확도 100% 보장 안 됨**: 짧은 1~2줄은 잘 나오지만 긴 문장·여러 말풍선은 깨질 수 있다 → 짧게, 컷당 말풍선 1개, Step 4 전수 검수 필수.
- **식자 타입은 "모양 묘사"로 근사**일 뿐 특정 폰트 지정·모양 100% 일관은 보장 안 됨(컷마다 편차). 핵심(speech/shout/sfx 무말풍선)은 잘 구분되나, 미세한 글꼴은 한계.
- 생성 60~120초/컷, 레퍼런스 연결 시 concurrency 2 이하 + 세션 누적 rate limit 주의(Step 2).

## 아직 안 들어간 것 (P2, 향후)
집중선·효과선·속도선, 스크린톤/톤 질감, 컷 전환·앵글 다양성 라이브러리, 플랫폼 업로드용 긴 이미지 분할 기준. — 앱 웹툰 편집기(미구현) 또는 후속 스킬 개선에서 다룬다. (장소·소품 시트 앵커링은 Step 2의 "장소·공간 일관성" 참조로 해결됨.)
