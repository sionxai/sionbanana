# Sion Banana Thumbnail

## When to use

작품이 완성된 뒤 **배포 단계 산출물**을 만들 때 쓴다 — 유튜브 썸네일, 포스터용 키비주얼, 영상 제목 카피, 설명란.

씬별 키이미지·스토리보드·레퍼런스 시트 생성은 이 스킬이 아니라 **`sionbanana-image-gen`** 을 쓴다. 세로 웹툰은 **`sionbanana-webtoon`**.

이 스킬은 `sionbanana-image-gen`의 자산(캐릭터 시트·로케이션 시트·오브젝트 시트·공간 마스터)이 이미 있다고 가정한다. 없으면 그 스킬을 먼저 쓴다.

---

## 썸네일은 스토리보드 컷과 요구가 다르다

| | 스토리보드 컷 | 썸네일 |
|---|---|---|
| 보는 크기 | 원본 또는 극장 | **모바일 피드 3cm** |
| 목적 | 서사 전달 | 클릭 |
| 글자 | 없음(간판만) | **제목이 화면의 주역** |
| 판정 | 시트·연속성 대조 | **줄여서 읽히는가** |

그래서 컷 검수 기준을 그대로 쓰면 안 된다. **판정은 실제 표시 크기로만 한다.**

## Phase 1 — 3안 탐색

성격이 다른 세 축으로 뽑는다. 각도만 바꾸면 세 장이 같은 그림이 된다.

| 축 | 구성 | 강점 / 약점 |
|---|---|---|
| **얼굴형** | 주인공 얼굴이 화면 절반, 나머지에 위협 요소와 여백 | 모바일에서 가장 강하다. 얼굴이 커야 클릭된다 / 설정 정보가 약할 수 있다 |
| **대치형** | 좌우 절반씩 나눠 양측을 대비 | 줄거리 전달력 최고 / 작아지면 다 뭉개져 **포스터에 가깝다** |
| **오브젝트·분위기형** | 상징 소품이나 적을 근접으로, 주인공 없음 | 분위기 최고 / **주인공이 없어 장르가 오해된다** |

프레임 복잡도는 **셋 이하**로 제한한다(`sionbanana-image-gen` §복잡도 예산과 동일).

### 여백을 프롬프트로 확보한다

제목이 들어갈 자리를 처음부터 비워라. 사후에 얹으면 얼굴이나 핵심 요소를 가린다.

> `★화면 왼쪽 절반은 흙먼지 낀 대로가 원경까지 뻗어 ★제목을 얹을 여백이 된다.`

**글자는 어두운 영역에 앉힌다.** 밝은 하늘에 얹은 제목은 아무리 키워도 168px에서 묻힌다.

## Phase 2 — 제목을 이미지에 그려 넣는다

### ★한글은 큰 전경 글자면 잘 나온다

배경 간판이 유사 한글로 뭉개지는 것을 보고 "제목은 합성해야 한다"고 판단하면 **틀린다.** 화면 폭의 절반을 차지하는 제목은 로마자·한글·숫자가 모두 또렷하게 나온다.

**갈리는 것은 언어가 아니라 크기다.** 작은 배경 간판은 뭉개지고 큰 전경 제목은 나온다.

### 화면에 나올 글자를 잠근다

명시한 것 외에 글자가 생기면 못 쓴다.

> `★★이 두 줄 외에 어떤 글자도 넣지 말 것 — 부제·간판 글씨·자막·로고·워터마크·크레딧 금지.`

### ★크기는 "화면 폭의 %"가 아니라 프레임 내 비율로 줘라

`화면 폭의 12%`는 안 잡힌다. 프레임 안에서 직접 비교되는 값으로 바꾸면 한 번에 나온다.

> `★1행 한 글자의 높이가 ★화면 세로의 5분의 1이다.`
> `★1행 전체가 ★화면 가로의 55~60%를 차지한다.`
> `★작고 얌전한 자막처럼 그리지 말 것 — 포스터 제목처럼 크다.`

`sionbanana-image-gen` §「결과가 아니라 물리를 써라」를 조판에 적용한 것이다.

### ★두 줄까지다. 세 줄은 쓰지 마라

실측: 세 번째 줄은 320px에서도 뭉개지면서 공간만 먹는다. 그 줄을 빼고 제목을 키우면 전체가 산다.

**빼야 할 문구가 아깝다면 영상 제목으로 옮겨라.** 썸네일에서 죽는 카피가 제목에서는 살아난다.

### 글자 층 구성

요소가 셋이면 **스크립트 종류를 섞고 크기·색으로 위계를 준다.**

```
로마자 제목 + 한글 제목    ← 가장 크게, 흰색
연도(숫자)                ← 절반 크기, 바랜 노란색
```

숫자와 로마자가 생성 안정성이 가장 높다. 색을 달리하는 이유는 흰색으로 통일하면 두 번째 줄이 묻히기 때문이다.

### 가독성 처리

- 굵은 검은 외곽선 (원본 1672px 기준 약 10px)
- 아래로 짧게 떨어지는 검은 그림자
- 글자 영역에 검은 그라데이션. 밝은 배경이면 필수, 어두운 배경이면 옅게
- **불투명 사각 판은 피한다** — 썸네일이 자막처럼 보인다

## Phase 3 — ★판정은 실제 표시 크기로만 한다

원본 해상도로 보고 판단하면 반드시 틀린다. 유튜브 실제 표시 폭으로 줄여서 보는 것이 **유일한 판정**이다.

```
모바일 피드      ≈ 320px
데스크톱 관련영상  ≈ 168px
```

### 시뮬레이션 스크립트

```bash
cd <repo> && SP=$(node -e "console.log(require.resolve('sharp'))")
node --input-type=module -e "
import sharp from '$SP';
const D='<썸네일 폴더>', names=['thumb-a','thumb-b','thumb-c'];
const rows=[[320,'모바일 피드 320px'],[168,'데스크톱 관련영상 168px']];
const P=10,LB=24,GAP=14, CW=P*2+320*3+GAP*2;
let CH=P; for(const [w] of rows) CH+=LB+Math.round(w*941/1672)+GAP*2;
const c=[]; let y=P;
for(const [w,lab] of rows){
  const h=Math.round(w*941/1672);
  c.push({input:Buffer.from('<svg width=\"'+(CW-P*2)+'\" height=\"'+LB+'\"><rect width=\"'+(CW-P*2)+'\" height=\"'+LB+'\" fill=\"#151515\"/><text x=\"4\" y=\"18\" font-family=\"monospace\" font-size=\"17\" fill=\"#ffcc55\">'+lab+'</text></svg>'),left:P,top:y});
  y+=LB+4; let x=P;
  for(const n of names){ c.push({input:await sharp(D+'/'+n+'.png').resize({width:w}).png().toBuffer(),left:x,top:y}); x+=w+GAP; }
  y+=h+GAP*2-4;
}
await sharp({create:{width:CW,height:CH,channels:3,background:'#2a2a2a'}}).composite(c).png().toFile('<출력>/sim.png');
"
```

### 실측 기준선

| 글자 높이 | 320px | 168px |
|---|---|---|
| 8% · 세 줄 | 제목은 읽히나 **부제 뭉개짐** | 제목도 위태 |
| **12% · 두 줄** | ✅ 확실히 읽힘 | ✅ 버팀 |

**168px에서 읽히지 않으면 그 안은 탈락이다.** 데스크톱 관련영상 노출이 유입의 큰 몫이다.

## Phase 4 — 영상 제목 카피

썸네일과 다른 **후크 전략**으로 3안을 만든다. A/B 테스트는 변수가 하나여야 읽힌다.

| 전략 | 형태 | 짝지을 썸네일 |
|---|---|---|
| **설정형** | 연도·지명·사건을 결합 | 대치형 또는 얼굴형 |
| **열세형** | 숫자 대비 | 얼굴형 (감정 이입 + 열세) |
| **톤형** | 장르 기대를 비틈 | 오브젝트·분위기형 |

**규칙:**
- 공백 포함 **40자 이내**. 모바일에서 잘린다
- 낚시성 과장(충격·레전드·소름) 금지
- **★결말을 제목에 쓰지 마라.** 단편에서 마지막 반전은 유일한 자산이다. 반전형 제목은 클릭률이 높아도 순손실이다
- 지명·고유명사는 **한글**이 검색에 유리하다. 로마자는 썸네일에 이미 로고로 박혀 있으면 충분하다
- 검색 태그성 접미(`| 단편영화`)는 글자 수를 먹지만 유입에 유리하다. 40자 여유가 있으면 붙인다

## Phase 5 — A/B 조합 설계

**9개 전부 돌리지 마라.** 표본이 쪼개져 아무것도 유의하게 안 나온다.

핵심은 **하나만 바꾸는 세 조합**이다:

```
1-A   대조군
2-A   같은 썸네일 · 제목만 교체  →  제목 효과 순수 측정
1-B   같은 제목 · 썸네일만 교체  →  썸네일 효과 순수 측정
```

여기에 도전자 1~2개를 더한다.

**대조군은 실측으로 정한다.** 자문이 어떤 안을 권하더라도, 표시 크기 시뮬레이션에서 약점이 확인된 안을 기준선으로 두지 마라.

## Phase 6 — 설명란

**첫 3줄이 승부다.** 모바일에서 「더보기」 전에 보이는 것이 그만큼이다. 전제·고립·전력을 세 줄에 압축한다.

구성 순서:

1. **후크 3줄** — 전제 / 왜 도움이 안 오는지 / 남은 것
2. **줄거리** — 결말 직전까지. 마지막 반전은 쓰지 않는다
3. **러닝타임 · 컷 수**
4. **등장인물** — 이름 (나이) — 역할
5. **챕터** — `MM:SS 제목`. 씬 제목이 내부 용어면 시청자용으로 바꿔 쓴다. 짧은 영상일수록 챕터가 체류에 도움이 된다
6. **만든 이야기** — 무엇이 재미있어서 만들었는지. 로케이션의 실제 근거
7. **제작 표기** — 생성형 AI 사용 시 **반드시 명시한다.** 유튜브가 합성 미디어 고지를 요구하고 숨기면 나중에 문제가 된다. 「AI로 만들었습니다」로 끝내지 말고 **시트를 먼저 확정하고 전 컷을 검수했다**는 공정을 적으면 AI 콘텐츠에 대한 방어가 된다
8. **해시태그** — 장르 · 소재 · 연도 · 지명

챕터 타임스탬프는 **STORY.md의 씬 헤더에서 뽑는다.** 손으로 세지 마라.

```bash
grep -E "^## 씬 [0-9] —" STORY.md
```

## 검수

썸네일도 Codex 교차검수가 유효하다. 단, **자문 입력에 시뮬레이션 이미지를 반드시 첨부한다.**

원본만 주면 "글자를 키워라" 정도의 일반론이 돌아온다. 320px·168px 축소본을 함께 주면 **무엇이 실제로 뭉개지는지와 구체적 수치**가 돌아온다.

체크리스트를 주지 말고 열어서 물어라 — `sionbanana-image-gen` §「검수 분업」과 동일하다.
