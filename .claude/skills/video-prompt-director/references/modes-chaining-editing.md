#### ② 실측 규칙 (2026-09-10~14 · `iru-dream-3`·`iru-sauna-sikhye`)

> **②는 두 그림을 보간(블렌드)할 뿐 카메라를 풀지 않는다** — 2026-09-14 실측으로 확정. 그전의 "카메라 무빙을 start/end 구도로 확정" 가정은 폐기했다.

- **②가 되는 컷**: 피사체가 **제자리**에서 국소적으로 바뀌는 컷. 환경이 극적으로 바뀌어도 되지만 **어떻게 바뀌는지를 연속 과정으로 써야** 한다 — 프롬프트에 **①시작 / ②전이 메커니즘 / ③끝**. 전이 어휘: 녹아 풀어진다·가늘어지며 흐려진다·부풀어 오른다·걷힌다·차오른다·떠오른다. (`iru-dream-3` 창가→구름, 아이 공포→미소, 구름→창턱 성공)
- **②가 안 되는 컷**: 카메라 무빙·프레임 횡단·유리 너머 시점 반전 → 형체가 녹고 유령 발이 생겼다(`iru-dream-3` V1 전량 탈락). ①+프롬프트로 가거나 컷을 나눈다. 판정 기준은 기하학이 아니라 **"그 변화를 연속 과정으로 쓸 수 있는가"**다.
- **★고정 카메라 원테이크는 시작=끝을 같은 키이미지로 준다(k→k).** ①로 만든 10초는 "no zoom, camera never moves closer"를 써도 **1.11배 푸시인**이 났고(2/2) 피사체가 **+29%** 커졌다. 같은 프롬프트를 ② k→k로 주자 배경 정합 배율 **1.00**·크기 유지·첫↔끝 프레임 평균 차이 **2.5/255**로 루프까지 닫혔다. 이후 ② 클립도 실측 4건 모두 배율 1.00. 대가: 동작이 조금 얌전해지고, 끝을 맞추느라 "놓았다 다시 다가가기" 같은 왕복 동작이 약해진다.
- **연장(10초+5초)**: 뒤 클립은 시작=앞 클립의 끝 키이미지, 끝=새 상태(엎드려 턱 괴기) 키이미지로 ②. 키이미지로 이으면 앞 클립 실제 마지막 프레임과의 차이가 약 2.7/255 — **2프레임 크로스페이드**(`xfade`)로 가리면 보이지 않고 총 프레임 수도 정확히 맞출 수 있다(241+121−2=360). 더 정확히 잇고 싶으면 앞 클립의 **실제 마지막 프레임**을 MCP `create_video`의 `source:{type:"upload", imagePath}`로 등록해 시작으로 쓴다(§프레임 체이닝 3 — HTTP `/api/video`는 이미지 ID만 받는다).

### 프레임 체이닝 — 15초 벽을 잇는 법 (2026-09-02 실측)

> `grok-imagine-video-1.5`에는 **`lastFrame`(끝프레임) 파라미터가 있다**(위 §영상 변환 3모드 — 2026-09-10 확인. 그전 "끝프레임 파라미터가 없다"는 기록은 폐기했다).
> 체이닝은 **유일한 방법이 아니라 다음 두 경우의 수단**이다: (1) 15초 상한을 넘겨 이어붙일 때, (2) 다음 컷의 끝 그림을 미리 만들 수 없을 때.
> 앞 컷의 끝 상태를 이미 알고 있다면 **체이닝보다 스타트앤드가 정확하다.**

**컷1의 마지막 프레임을 이미지로 등록해 컷2의 소스로 쓰면 연속이 유지된다** — 이음매 앞뒤 프레임차가 인접 프레임 수준이다.

| 비교 | YAVG(휘도 차) | 판정 |
|---|---|---|
| 같은 영상 인접 프레임(0.04s) | 2.3 | 기준 |
| **체이닝 이음매**(컷1 끝 → 컷2 첫) | **3.6** | 연속 |
| 같은 장면 2.5초 시간차 | 34.8 | 점프 |
| 전혀 다른 장면 | 57.1 | 불연속 |

절차 (MCP — 다른 세션에서도 동일):
1. 컷1 생성: `create_video` → `get_video` ready → `videoPath`.
2. **마지막 프레임을 정확히** 추출 (`-sseof -0.1`은 2프레임 앞을 잡는다 — 정확 추출과 YAVG 2.06 차이):
   ```bash
   N=$(ffprobe -v error -count_frames -select_streams v:0 -show_entries stream=nb_read_frames -of csv=p=0 cut1.mp4)
   ffmpeg -i cut1.mp4 -vf "select='eq(n\,$((N-1)))'" -vsync 0 -frames:v 1 data/frames/cut1-end.png
   ```
   파일은 **시온바나나 저장소 안**(`data/frames/` 등)에 둔다 — upload 소스는 repoRoot 내부 경로만 받는다.
3. 컷2 생성: `create_video` `source:{type:"upload", imagePath:"<저장소 안 절대경로>"}` (SB WO-006 이후 MCP). 재시작 전 구 MCP 프로세스면 폴백: 프레임을 `data/images/<버킷>/<커스텀id>.png`로 복사한 뒤 `source:{type:"imageId", imageId:"<커스텀id>"}` — `readImageById`가 전 버킷을 스캔하므로 사이드카 없이 해석된다(실증: `data/images/refs-hope/chain-dragon-cut1-end.png`).
4. 컷2 프롬프트: ①블록 첫 문장을 **"Continues seamlessly from this exact frame: <컷1 마지막 상태 묘사>"**로 열고, 조명·카메라·정체성 락 문구는 컷1과 동일하게 복사한다. 새 피사체·새 장면 금지 철칙 그대로.
5. 이어붙이기 (같은 해상도·코덱이면 재인코딩 없이 — 실측 15s+15s → 30.1s, video+audio 유지):
   ```bash
   printf "file '%s'\nfile '%s'\n" cut1.mp4 cut2.mp4 > list.txt
   ffmpeg -f concat -safe 0 -i list.txt -c copy joined.mp4
   ```
6. 이음매 검증 — 컷1 마지막 프레임 vs 컷2 첫 프레임(`ffmpeg -i cut2.mp4 -frames:v 1 cut2-first.png`):
   ```bash
   ffmpeg -i cut1-end.png -i cut2-first.png -filter_complex "[0]format=gray[a];[1]format=gray[b];[a][b]blend=all_mode=difference,signalstats,metadata=print:key=lavfi.signalstats.YAVG:file=-" -f null - 2>&1 | grep -o 'YAVG=[0-9.]*'
   ```
   **YAVG ≤ 5 = 연속, 30 이상 = 눈에 띄는 점프 → 컷2 재생성.**

주의: 오디오는 컷마다 새로 생성된다 — 대사는 컷 경계에서 문장을 닫는다. 컷을 넘는 BGM 연속성은 **보장되지 않는다(미검증 가정)** → 긴 시퀀스의 음악은 후반 편집에서 한 트랙으로 까는 편이 안전하다.

### 편집 조립 — 네이티브 오디오를 버리지 마라 (2026-09-03 사고 기록)

`[사고]` 5컷 클립을 `concat=n=5:v=1:a=0`으로 조립해 납품하고 **"사운드 미착수"라고 보고**했다.
대표 지적 후 `ffprobe`로 확인하니 **전 클립에 AAC 48kHz 스테레오가 −30~−42dB로 이미 들어 있었다.**
원인은 단순하다 — **모델이 무음이라고 가정하고 한 번도 확인하지 않은 것.**

**규칙: 조립 전에 오디오 스트림을 반드시 확인한다. 안 들린다고 없는 게 아니다** (네이티브 오디오는 낮게 깔린다).

```bash
ffprobe -v error -select_streams a:0 -show_entries stream=codec_name,sample_rate,channels -of csv=p=0 cut1.mp4
ffmpeg -i cut1.mp4 -af volumedetect -f null - 2>&1 | grep mean_volume   # −40dB도 "있음"이다
```

- **`-c copy` concat은 오디오를 유지한다** (프레임 체이닝 절의 방식). 트림·페이드가 필요 없으면 이쪽이 안전하다.
- **`filter_complex`로 트림·페이드를 걸 땐 `a=1`을 빠뜨리는 순간 소리가 사라진다.** 에러가 아니라 조용히 없어진다.

> **폐기된 레시피(2026-09-14 실측) — 쓰지 마라:** 컷마다 `afade` 0.2초 + 단일 패스 `loudnorm`은 **소리를 깨뜨렸다**(`iru-dream-3` V5, 대표 지적 "소리 깨짐"). ① 컷마다 페이드 아웃·인을 걸어 이음매 16곳 중 15곳이 −20dB보다 깊게 꺼졌다(최악 −116dB, 무음). ② 동적 `loudnorm`이 컷마다 게인을 +18~−14dB로 흔들어 펌핑이 났다. ③ `loudnorm`이 샘플레이트를 올린 채 출력돼 AAC가 96kHz로 인코딩됐다. ④ 배속 컷의 소리를 `atempo`로 늘여 웃음·울음이 뭉개졌다.

**컷별 트림 + 음량 맞춤 + 이음매 크로스페이드 + 리미터** (`iru-dream-3` V6 이후·`iru-sauna-sikhye` 최종본 방식):

1. **클립마다 음량부터 잰다**(`ebur128`). 생성 오디오는 같은 장면·프롬프트에서도 **−58~−28 LUFS**로 들쭉날쭉하다(`iru-sauna-sikhye` 클립 6개).
2. **배속 컷도 소리는 늘이지 않는다.** 1배속 원본에서 구간을 골라 붙이고, 소리 사건의 동기는 `구간 시작 = 사건 실측 시점 × (1 − 1/배율)`로 맞춘다(울음·웃음 싱크 오차 3–5ms). 영상 배속은 2.0배 이하, 손 흔들기처럼 모두가 속도를 아는 동작은 **감속 램프**(2.0배 → 1.0배 smoothstep)로 정상 속도에 착지시킨다.
3. **컷별 정적 게인**(목표 음량 − 측정값, 잡음 과증폭 방지 −10~+12dB 클램프) → **등전력 크로스페이드 0.08~0.1초**(`acrossfade c1=qsin:c2=qsin`). 무음 인서트·대사 끝 공백은 앞뒤 컷 소리를 J/L컷으로 걸친다.
4. **이음매 양쪽의 바닥 소음이 다르면 뒤 클립 게인을 램프한다** — 바닥 소음을 맞춘 값에서 시작해, 뒤 클립 첫 소리 사건 전까지(약 0.5초) 통합 음량을 맞춘 값으로 옮긴다. 고정 게인으로 붙였더니 배경음이 이음매에서 7dB 뚝 떨어졌다(`iru-sauna-sikhye` V3).
5. **마스터 정적 게인은 리미터 영향으로 고른다** — 400ms 순간 음량(`ebur128` M)을 리미터 전후로 비교해 **평균 −0.5dB·최악 −4dB 이내**인 가장 큰 게인. 순간음이 뾰족한 클립은 −16 LUFS까지 깨끗하게 못 올린다 — 압축기(피크 검출)는 음량과 피크를 같이 낮춰 소용없었고, 소프트 클리퍼는 전체를 뭉갰다. **억지로 올리지 말고 목표 미달을 보고한다.**
6. `alimiter` −2~−3dBFS(`limit` 0.7943~0.7079, `latency=true`) → `aresample=48000`. 영상은 원본 fps(grok 24fps) 그대로 — 30fps로 바꾸면 프레임이 중복된다.

```bash
# 두 클립 예: 영상은 2프레임 크로스페이드, 소리는 0.08초 등전력 크로스페이드.
# B 게인은 G0(이음매 바닥 소음 기준)에서 0.55초 동안 GB(통합 음량 기준)로 램프, 마스터 게인 M은 5번 기준으로 탐색
ffmpeg -i A.mp4 -i B.mp4 -filter_complex "\
[0:v]fps=24,settb=AVTB,format=yuv420p[va];[1:v]fps=24,settb=AVTB,format=yuv420p[vb];\
[va][vb]xfade=transition=fade:duration=0.083333:offset=<A길이-0.083333>[v];\
[0:a]highpass=f=80,atrim=0:<A길이>,asetpts=PTS-STARTPTS[aa];\
[1:a]highpass=f=80,asetpts=PTS-STARTPTS,volume=volume='pow(10,(if(lt(t,0.55),G0+(t/0.55)*(GB-G0),GB))/20)':eval=frame[ab];\
[aa][ab]acrossfade=d=0.08:c1=qsin:c2=qsin,volume=<M>dB,alimiter=limit=0.7079:attack=5:release=60:level=false:latency=true,aresample=48000[ao]" \
-map "[v]" -map "[ao]" -c:v libx264 -pix_fmt yuv420p -crf 18 -preset slow -c:a aac -b:a 192k -ar 48000 out.mp4
```

- 여러 컷을 `concat`으로 이을 때도 `a=1`을 빠뜨리지 않는다 — **이 한 글자가 오디오 유무를 가른다.**
- 조립 스크립트 실례(게인 탐색·램프·J/L컷 포함): `makemov/works/iru-dream-3/04-영상/_runs/v5/build6.py`(23컷), `makemov/works/iru-sauna-sikhye/04-영상/_runs/r6/build4.py`(2클립).
