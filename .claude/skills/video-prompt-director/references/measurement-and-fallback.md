## 실측 방법론 — 판정 3축 · 측정 커맨드 · 실험 규칙 7 (SKILL.md §실측 방법론의 A급·B급 표를 확정한 방법)

### 판정 3축 — 한 숫자로 보지 않는다

| 축 | 무엇 | 무엇이 결정하나 |
|---|---|---|
| **축1 초기 재구도** | 0.2초 시점의 소스 대비 이탈 | **소스 이미지의 피사체 크기** |
| **축2 누적 드리프트** | 0.2초 → 종료 시점의 증가분 | **프롬프트** |
| **축3 변동폭** | 동일 프롬프트 3표본의 축1·축2 범위 | **이게 판정 하한이다** |

`[사실]` 소스를 바꿨더니 축1은 절반이 됐는데 축2는 오히려 나빠졌다. **두 축은 함께 움직이지 않는다** — 합쳐서 "이탈"이라고 부르면 무엇이 개선됐는지 알 수 없다.

> **축3이 제일 중요하다.** 한 소스에서 축2 변동폭이 13.6 → 0.58로 줄었다. 이탈량이 준 것보다 큰 의미다 —
> **재현성을 얻었다**는 뜻이고, 그래야 프롬프트 실험의 판정이 가능해진다.
> 변동폭이 13.6일 때 3표본으로 프롬프트를 비교한 것은 처음부터 무의미했다.

**영역을 나눠 재고, 섞어서 하나로 말하지 않는다** (720×1280 기준 예):
```bash
# CROP 예: 상단배경 720:448:0:0 / 하단 720:320:0:960 / 중앙피사체 432:448:144:448
ffmpeg -v error -i SRC.png -i FRAME.png -filter_complex \
 "[0:v]crop=CROP,format=gray[x];[1:v]crop=CROP,format=gray[y];[x][y]blend=all_mode=difference,signalstats=stat=tout,metadata=print:file=-" \
 -f null - 2>/dev/null | grep -m1 YAVG
```

### 실험 규칙 7

1. **한 번에 한 칸만 바꾼다.** 두 칸 이상 바꾼 실험은 결과가 좋아도 **판정 불능**으로 기록한다.
2. **3표본. 표본 사이에 프롬프트를 바꾸지 않는다** (D-008).
3. **세 축을 따로 기록한다.** 축1·축2를 하나로 합치지 않는다.
4. **변동폭(축3)보다 작은 차이는 "판정 보류"다.** 개선이라고 쓰지 않는다.
5. **소스 이미지는 실제로 납품할 것을 쓴다.** 새 소스는 첫 실험에서 기준선 3표본으로 **축3부터** 잰다 — 변동폭이 크면 "이 소스에서는 프롬프트 미세 실험이 불가"라는 결론 자체가 성과다.
6. **동시 요청 3건은 429.** 순차로 돌린다. 즉시(0.06초) 실패는 업스트림 502이지 프롬프트 문제가 아니다.
7. **재시도는 실패가 아니다**(D-008). 단 **프롬프트를 바꾸면서 재시도하지 않는다** — 무엇이 효과였는지 영영 알 수 없다.

> **"판정 불능"을 "실패"라고 부르지 않는다.** 실패와 미판정은 다르다.
> 그리고 **자기 규칙도 반증되면 강등한다** — "소스 피사체가 1/4.6보다 작으면 재현되지 않는다"는 A급 규칙은
> 1/7.1 소스가 전 이력 최저 드리프트를 내면서 강등됐다. 표본 3건으로 세운 규칙은 표본 3건으로 무너진다.

## 폴백 — grok 한도가 소진되면 MiniMax H3 (2026-09-03 실측 3회)

`[사실]` **H3는 폴백으로 쓸 수 있다. 단 grok과 같은 방식으로 쓰면 밋밋해진다 — 제작 방식을 바꿔야 한다.**

| | grok-imagine-video-1.5 (주력) | **MiniMax H3 768P (폴백)** |
|---|---|---|
| 해상도 | 720×1280 | 768×1344 (약간 높음) |
| 참조 이미지 | **1장** | **9장** |
| 표정·동작 | **강함** | 약함 — 거의 정지 |
| 캐릭터 유지 | 키이미지로 잡아야 함 | **앵커 9장으로 잡힘** |
| 생성 시간 | 약 40초 | 약 5분 (2K는 13분) |
| 비용 | xAI 프록시 별도 | 12.5크레딧 / 5초 → **30초 1편 = 75크레딧** |

`[사실]` **앵커 9장은 작동한다** — 털색·이마 흰 포인트·흰 발끝·늘어진 귀가 4프레임 내내 유지됐고 배경도 그대로였다.
`[사실]` **표정 약세는 해상도·앵커와 무관하다** — 2K든 768P든, 앵커가 있든 없든 3회 모두 밋밋했다. **모델 특성으로 확정.**

**폴백 레시피 — 약점을 그대로 활용한다.** H3는 grok보다 **보존을 충실히** 한다(거의 안 움직이므로).

| 항목 | grok 방식 | **H3 방식** |
|---|---|---|
| 키이미지 | 자세·크기·정체성 확정 (철칙 2) | 거기에 더해 **표정까지 절정 상태로** 확정 |
| 영상 프롬프트 | 동작을 지시 | **미세 동작만.** 표정은 "유지하라"만 |
| 컷 설계 | 한 컷에 한 동작 | 질주·점프 같은 큰 동작은 **컷을 쪼개거나 회피** |
| 참조 | 키이미지 1장 | **primary(키이미지) + 앵커 8장 = 9장** |

잘 맞는 컷: 풍경·무드·정지에 가까운 리액션·마지막 여운. 피할 컷: 질주·점프·격한 몸짓.

호출은 BBANANA MCP. **앵커는 bbanana.ai 통합스토리지에 미리 올려두고 계속 재사용한다**
(MCP `upload_image`는 base64 인라인만 받는데 2K 키이미지는 그 한도를 넘어 세션에서 직접 업로드가 안 된다 — 수동 업로드 1회).

```
list_my_uploads(media_type:"image")     → 앵커 URL 확보
generate_video(model:"MiniMax H3", resolution:"768P", aspect_ratio:"9:16", duration:5,
               image_urls:[<키이미지>, <앵커1..8>], prompt:"…")
get_status(taskId)                       → 약 5분
```

**프롬프트 첫 줄에 참조 이미지의 역할을 명시**한다 — "첫 번째 참조가 시작 프레임이고, 2~9번은 이 캐릭터의 생김새를 고정하는 캐릭터 시트다."
안 하면 앵커의 스튜디오 배경이 장면에 섞인다.

미시험 후보: `H3 Self-hosted` 8크레딧(같은 오픈 가중치, 품질 동일 여부 **미확인**) · `Wan 3.0` 14크레딧(참조 10장·네이티브 오디오) · `Seedance 2.5` 32크레딧(참조 10장).
